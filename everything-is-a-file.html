📁 Why Does Linux Have /proc?

You open a Linux terminal and run:

ls /

You get a bunch of directories:

bin
boot
dev
etc
home
lib
proc
root
run
sys
tmp
usr
var

Most of these make some amount of sense.

/home contains users' files.

/etc contains configuration.

/tmp contains temporary files.

But then there's:

/proc

You open it:

ls /proc

And suddenly you get something like:

1
2
3
4
...
cpuinfo
meminfo
mounts
uptime
version

What are all those numbers?

And why does a directory contain things called cpuinfo and uptime?

Welcome to one of Linux's stranger ideas.

🧠 /proc isn't really a normal directory

The first thing to understand is that /proc is a virtual filesystem.

Normally, when you create a file, its contents are stored somewhere on a physical storage device:

SSD
 │
 └── file.txt
       │
       └── "Hello"

But /proc is different.

The files you see there aren't ordinary files sitting on your SSD.

Linux creates them dynamically to expose information from the running kernel.

You can think of /proc as a window into what the operating system is currently doing.

             Linux kernel
                  │
        ┌─────────┼─────────┐
        │         │         │
       CPU       RAM     processes
        │         │         │
        └─────────┼─────────┘
                  │
                  ▼
               /proc

The filesystem gives programs a convenient way to ask the kernel questions.

🔢 So what's /proc/1?

Remember all those numbers?

They're mostly process IDs, or PIDs.

Every running process on Linux gets a number.

For example:

ls /proc

might show:

1
42
317
842
1294
...

Those directories correspond to processes.

Try:

ls /proc/1

You'll see a whole collection of strange-looking entries.

You can also ask Linux what process PID 1 actually is:

ps -p 1

On many modern Linux systems, you'll see something related to:

systemd

PID 1 is special.

It's the first userspace process started by the kernel and is responsible for a bunch of important system-management duties.

If you want to learn more about that, you've just discovered your first rabbit hole.

🖥️ /proc/cpuinfo

Try:

cat /proc/cpuinfo

You'll get information about your CPU.

Depending on your processor, you might see things such as:

processor
vendor_id
cpu family
model
model name
cpu MHz
cache size
flags

Where did this file come from?

You didn't create it.

It isn't sitting on your SSD.

The kernel is providing the information through the /proc filesystem.

This means that cat /proc/cpuinfo is essentially asking Linux: "Tell me about the CPU."

🧠 /proc/meminfo

Now try:

cat /proc/meminfo

You'll see information about memory:

MemTotal
MemFree
MemAvailable
Buffers
Cached
SwapTotal
SwapFree

Again, these aren't ordinary text files that some program constantly rewrites.

They're an interface provided by the kernel.

The information can change as the state of the system changes.

For example, if you open a large application and run cat /proc/meminfo again, some values will have changed.

The "file" is effectively giving you a snapshot of the system's current state.

⏱️ /proc/uptime

Try:

cat /proc/uptime

You might get something like:

18342.51 29173.42

The first number represents how many seconds the system has been running.

So if your computer has been running for roughly five hours, the first number will be around 18000.

Again: That number isn't sitting on your SSD. Linux generates it when you read the file.

👀 The really interesting part

You can actually watch /proc change.

Open one terminal and run:

watch ls /proc

Then open programs.

You'll notice new numbered directories appearing as processes start.

Close programs and those directories disappear.

That's because the directories correspond to currently existing processes.

Start Firefox ➔ Firefox gets a PID ➔ /proc/ appears ➔ Firefox exits ➔ /proc/ disappears

The filesystem is effectively reflecting what's happening inside the running operating system.

🔬 Look inside a process

Suppose you have a process with PID 1234.

You can look inside:

ls /proc/1234

You might find:

cmdline
cwd
environ
exe
fd
maps
status
stat

These expose different pieces of information about the process.

For example, cat /proc/1234/status can show information about the process's state, memory usage, IDs and more.

And readlink /proc/1234/exe can show which executable the process is running.

One particularly interesting entry is /proc/1234/fd. That's the process's file-descriptor directory.

🤯 Is /proc stored in RAM?

Not in the normal sense.

You might hear people describe /proc as a "RAM filesystem", but that's an oversimplification.

procfs is a virtual filesystem implemented by the kernel.

It doesn't represent ordinary persistent storage. Its contents are generated from kernel information.

🐧 Why did Linux do this?

This is part of a much older Unix idea: Give programs a simple interface to interact with the system.

Instead of requiring every program to have a completely different mechanism for asking the operating system about processes, devices and system information, Linux can expose information through familiar filesystem interfaces.

Programs already know how to open, read, write, and close files.

👀 /sys is watching you too

Run ls / and you'll probably see proc, sys, and dev.

/sys is another important virtual filesystem (sysfs) that exposes information about devices, drivers, the kernel and hardware-related objects.

🧩 /dev

Look inside ls /dev and you may see entries like null, zero, random, tty, or nvme0n1.

Some of these are device files. For example, your SSD might appear as /dev/nvme0n1.

And then there are things like /dev/null, which is essentially a black hole for data:

echo "hello" > /dev/null

🧠 The bigger idea

At this point, Linux's filesystem starts looking less like a folder full of documents and more like an interface to the entire computer:

/home   → your files
/etc    → configuration
/proc   → processes/kernel information
/sys    → devices/kernel information
/dev    → device interfaces

And this leads directly into one of the most famous ideas inherited from Unix: "Everything is a file."

🧪 Try it yourself

If you're running Linux, try these:

Find your PID:

echo $$

Look at information about the shell you're currently using:

ls /proc/$$
cat /proc/$$/status
readlink /proc/$$/exe

🕳️ Rabbit Hole → PID 1

Remember PID 1? Go investigate it:

ps -p 1 -o pid,comm,args
ls /proc/1

📝 TL;DR

/proc is a virtual filesystem provided by the Linux kernel. Its contents aren't ordinary files stored on your SSD.

It provides a filesystem-like way to access information about running processes, CPU information, memory, system uptime, and kernel state.

The numbered directories represent process IDs and appear/disappear as processes start and stop.
