🧟 What Is a Zombie Process?

You run a program.

It finishes.

So... it's gone, right?

Not quite.

Sometimes Linux keeps a tiny piece of the process around even after it has finished running. It isn't running, using CPU, or plotting anything. It's a zombie process.

🧠 The short answer

A zombie process is a process that has finished executing but still has an entry in the process table because its parent process hasn't collected its exit status yet.

Parent ➔ Child (running) ➔ Child (finished) ➔ Parent delays wait() ➔ Zombie 💀

👶 Why do processes have parents?

When a Linux process creates another process, the new process has a parent process.

Check process relationships with:

ps -ef
  • PID: Process ID (Unique ID for the process).
  • PPID: Parent Process ID (PID of the parent).

💀 How does a process become a zombie?

When a child process exits, the kernel retains its exit code (e.g., Exit status: 0) until the parent collects it.

🧹 wait() cleans it up

The parent calls a system call like wait(), receives the exit status, and the zombie entry disappears.

🟢 What does exit code 0 mean?

Check the previous command exit status with:

echo $?

An exit status of 0 means success. Non-zero values indicate errors.

🔍 Finding zombies

Run ps aux and look for status Z or <defunct>:

USER   PID   STAT   COMMAND
user   420   Z      [program]

🧠 Zombies don't use CPU

Zombies consume zero CPU cycles and almost no memory. They only occupy an entry slot in the process table.

👻 Zombie vs Orphan

  • Zombie: Dead child + living parent who hasn't waited yet.
  • Orphan: Living child + dead parent (re-parented to PID 1).

👑 PID 1 enters the story

PID 1 (usually systemd) automatically adopts orphan processes and cleans them up when they terminate.

🌳 Linux processes form a tree

Inspect the system process hierarchy using:

pstree

🚨 Can you kill a zombie?

No. You cannot kill a zombie with kill -9 because it is already dead. To remove zombies, you must get the parent process to call wait() or terminate the parent process.

📝 TL;DR

A zombie process is simply a finished task whose exit paperwork hasn't been collected by its parent process yet.
